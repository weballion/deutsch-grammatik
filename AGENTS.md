# Deutsch: Граматика — инструкция для агентов

Единый источник правды по проекту: продукт (бывшее «ТЗ»), правила составления заданий (бывшая «Грамматика») и порядок работы. Банк заданий лежит отдельно в `data/tasks.json`.

Язык общения с пользователем — русский. Язык интерфейса приложения и банка заданий (подсказки, правила блоков) — украинский или русский, выбирается автоматически по языку Telegram или вручную в настройках (раздел 2, «Язык интерфейса»). Задания — на немецком.

## 1. Что это

Личное приложение для тренировки немецкой грамматики (A2–B2) на телефоне: тесты по грамматическим блокам, баллы, статистика успеваемости по блокам. Один пользователь, без входа.

- **Сейчас:** Telegram Mini App (раздел 9) — `index.html` + `data/tasks.json` (уровень A2–B2) и `data/tasks_a1a2.json` (уровень A1–A2), без ИИ, только банк заданий, хранение через Telegram CloudStorage. Отдельный раздел «Слова» — тренировка лексики по банку слов `data/words_<уровень>.json`.

## 2. Принятые решения

| Вопрос | Решение |
| --- | --- |
| Источник заданий | Только готовый банк `data/tasks.json`, без ИИ. Свободные ответы без точного совпадения — самооценка |
| Пополнение банка | Только дописываем: новые задания по материалам курсов, плохие — удаляем по замечаниям. Весь банк не перегенерируем. Ядро фиксированных блоков (сейчас у M — список глаголов с предлогами из учебника, `choice`) не генерируется ИИ и не переписывается; остальное дописывается как обычно (у M — задания о возвратных глаголах, `choice`/`reflexive`) |
| Блоки | 14 блоков A–N (раздел 6). Новые блоки — только после согласования с пользователем. По умолчанию выбраны все |
| Уровень | A2–B2 (по умолчанию, все 14 блоков) и A1–A2 (7 урезанных блоков, свой банк `data/blocks_a1a2/` → `data/tasks_a1a2.json`) — переключатель в настройках. У каждого уровня свои настройки (количество, блоки, типы), прогресс и сохранённый тест — не пересекаются |
| Количество заданий | 5 / 10 / 15 / 30 заданий **на каждый выбранный блок** (раньше называлось «Сложность» с подписями Легко/Средне/Сложно — переименовано и упрощено до цифр, это объём теста, а не трудность). 30 — для прохождения одного блока отдельно от остальных с большей глубиной; поскольку количество применяется на каждый выбранный блок, при нескольких выбранных блоках даёт пропорционально больший тест — это ожидаемо, не баг |
| Состав блока | Задания блока делятся по типам в пропорциях (`types` блока); пользователь меняет их в настройках |
| Баллы | Верно 1, почти 0,5, неверно 0 |
| Слабый блок | Доля баллов < 70% за всю историю прохождений блока — только визуальная подсветка на экране «Статистика» (раздел 3), ни на что больше не влияет |
| Индикатор блока в настройках | Справа у каждого блока — шкала из 4 делений (по 25%, округление; при 1–24% горит одно деление) и процент за всю историю (`{s, n}`). Цвет всех горящих делений: < 50% — `--bad`, 50–69% — `--half`, ≥ 70% — `--ok`. Нет данных — 4 серых пустых контура и «—». Меньше 10 решённых заданий — деления полупрозрачные (данных мало) |
| Перевод | Украинский или русский (по языку интерфейса) → немецкий |
| Язык интерфейса | Украинский или русский. Автоопределение по языку Telegram (`initDataUnsafe.user.language_code`: начинается на `ru` → русский, иначе, включая запуск вне Telegram, → украинский) при каждой загрузке, пока пользователь не выбрал язык вручную в настройках — тогда выбор сохраняется (`dg_lang`) и больше не зависит от Telegram. Общий для обоих уровней (A2–B2/A1–A2) ключ, как тема и кнопки ä ö ü ß |
| Кнопки ä ö ü ß | Опция в настройках, по умолчанию выключена |
| Дизайн | «Тёмный» (бывший Классический, по умолчанию, светлая/тёмная по системе), «Светлый» (бывшая Лаванда) и «Glass» — переключатель в настройках, меняет только CSS-переменные темы (цвета, скругления, тени, декоративные пятна фона, токены маскота и стеклянных элементов) без изменений вёрстки/логики. «Светлый» и «Glass» всегда сохраняют свою палитру (темного/светлого варианта нет) и в Telegram игнорируют живые цвета хоста (`themeParams`) — это фиксированные авторские палитры. Внутренние ключи (`classic`/`lavender`/`liquid`, `data-theme`, значение `dg_theme`) не переименованы при смене подписи в интерфейсе (так уже было с лавандой → «Светлый», затем «Liquid Glass» → «Glass») |
| «Как это работает» (ⓘ) | Экран с описанием логики. **Обновлять при каждом изменении функционала или логики** |
| Раздел «Слова» | Отдельный тест, не блок: кнопка «Слова» на главной. Слово на языке интерфейса → выбрать немецкое из 4 вариантов, или наоборот (направление: туда / обратно / «Микс» — случайно для каждой карточки; настройка на экране «Слова», общая для уровней). Неверные варианты приложение берёт из банка само: той же части речи и без совпадений по смыслу. Режим ответа «Варианты / Ввести» (на экране «Слова», общий для уровней): при «Ввести» слово пишется в поле — немецкое с артиклем, перевод — любое из значений (части `ru`/`uk` через `,`/`;`, без скобок); сравнение без регистра и знаков препинания, ё = е; не совпало — самооценка «Верно / Неверно» рядом с эталоном. Тест «Старт» — проход по всему банку в случайном порядке, каждое слово один раз; незаконченный сохраняется («Пауза» → «Продолжить»), новый «Старт» его сбрасывает (с подтверждением). Короткие тесты по «Новым» и «Ошибкам» (раздел 8) не сохраняются и основной не трогают («Закончить» → итог). Настройки две — режим ответа и направление. Банк слов свой у каждого уровня, перед каждым пополнением уровень уточняется. Фильтр по урокам — позже |
| Не входит | Шеринг, вход, несколько пользователей |

## 3. Экраны

1. **Главная:** заголовок «Deutsch / Übungen» (одинаковый на обоих языках; на узких экранах шрифт уменьшается, длинный текст обрезается многоточием, а не наезжает на иконки); иконки «Статистика» / ⓘ / ⚙ сверху справа; большая кнопка «Старт», под ней строка «уровень · блоки · N заданий» (нажатие → настройки), под ней кнопка «Слова» (раздел «Слова», экран 8); «Продолжить тест» (если есть незаконченный); журнал «История тестов (последние 30)» — дата/время, блоки, баллы и процент каждого пройденного теста, сначала 3 последних, остальные разворачиваются по кнопке «Показать ещё N» под списком; в раскрытом виде та же кнопка — «Свернуть список».
2. **Настройки:** язык интерфейса (Українська / Русский); уровень (A2–B2 / A1–A2 — свой банк заданий и слов, свой прогресс); количество заданий (5 / 10 / 15 / 30 на блок); дизайн (Тёмный / Светлый / Glass — только оформление, экраны и логика те же); «Показать результат в конце»; кнопки ä ö ü ß; список блоков (Все / Снять; карточка выбранного блока — с тонкой обводкой и свечением цвета акцента темы), у каждого уровень, пример, индикатор успеваемости (4 деления + процент, раздел 2) и раскрывающийся состав типов (ползунок на каждый тип, подпись показывает расчётное число для текущего количества — «N из M», «Сбросить к стандарту»; позиция ползунка = доле типа в блоке, `max` ползунка = сумме весов типов). Сохраняются. Внизу — красная текстовая кнопка «Сбросить всю статистику» → попап с подтверждением («Сбросить» / «Отмена», ✕, тап по фону, «Назад»): обнуляет у текущего уровня `{s, n}` блоков, счётчики показов и журнал истории; настройки, незаконченный тест и прогресс «Слов» не трогает.
3. **Статистика:** отдельный экран (иконка на главной) — средний процент баллов по каждому блоку за всю историю прохождений: шкала из 4 делений (как индикатор в настройках, раздел 2) и процент, блок ниже 70% — процент красным.
4. **Как это работает:** описание логики (тест, источники заданий, уровень, баллы, раздел «Слова», история тестов, статистика по блокам, прочее) и дата обновления описания.
5. **Квиз:** одно задание на экране, «Блок X · название», тип, «Вопрос N из M», баллы, прогресс, «Отменить тест» с подтверждением. Незаконченный тест сохраняется после каждого ответа (переживает закрытие приложения). Название блока («Блок X · название») нажимается — во всплывающем окне шпаргалка по грамматике блока (`about`: правила, примеры, таблицы), закрывается круглой кнопкой ✕, тапом по фону или системной «Назад». Во всех заданиях, кроме `translate`, — кнопка перевода, по нажатию показывает/скрывает перевод предложения (`tr`) прямо под текстом задания, до ответа: у `choice`/`fill`/`reflexive`/`combine` — рядом с немецким текстом, у `fix`/`build` (там текст в поле или в чипах) — рядом с формулировкой задания.
6. **Ответ:** зелёный / жёлтый / красный, эталон, у заданий с пропуском (`fill`/`choice`/`reflexive`) — всё предложение целиком с верным ответом (жирным; подсказка в скобках убирается, `-` = ничего не вставлять), подсказка, у блока M — перевод и заметка про другие предлоги глагола (если есть). Самооценка: свой ответ рядом с эталоном и кнопки «Верно / Почти / Неверно». Опция «Показать результат в конце» скрывает оценку до итога.
7. **Итог:** баллы всего и по блокам, разбор ошибок (всегда), кнопки «Пройти ещё раз», «На главную».
8. **Слова** (кнопка на главной, под «Старт»): заголовок с уровнем; четыре цифры «Все / Новые / Ошибки / Скрытые» — каждая нажимается и открывает список слов с переводом (у «Ошибок» — сколько верных подряд из 4), в списках «Новые» и «Ошибки» кнопка «Пройти тест» (короткий, несохраняемый); в «Скрытых» у каждого слова «Показывать снова» и кнопка «Скопировать список» (уровень + строки «id слово — перевод») — пользователь присылает его агенту, чтобы заменить или исправить слова; «Продолжить» с полосой и «Пройдено X из Y», если основной тест не закончен; переключатели «Ответ: Варианты / Ввести» и направления; «Старт». Если банка слов у уровня нет — сообщение.
9. **Карточка слова:** счёт «✓ N · ✗ M», «K из M» по колоде, слово, 4 варианта или поле ввода (с кнопками ä ö ü ß, если они включены и ответ на немецком); кнопка озвучки (динамик) — `speechSynthesis` браузера, `de-DE`, скорость 0,9, голос телефона: у немецкого слова в вопросе — сразу, при вопросе на языке интерфейса — только после ответа (у слова и у примера `ex`), чтобы не подсказать; нет немецкого голоса — тост с советом установить; без `speechSynthesis` кнопки не показываются; в заданиях озвучки пока нет; после ответа — верно/неверно, полная форма слова (артикль, мн. число, управление) с переводом и пример предложения (`ex`) с переводом, «Дальше» и под ней текстовая кнопка «Не показывать в тестах» (слово уходит в «Скрытые»: не попадается ни в тестах, ни среди вариантов, не считается во «Все/Новые/Ошибки»). «Пауза» (и системная «Назад») в основном тесте сохраняет его и возвращает на экран «Слова»; в коротком тесте вместо неё «Закончить» → итог. После последней карточки — итог: верных из N, процент, слова с ошибками, «Ещё раз» / «К словам».

Интерфейс простой, под телефон, 3 темы оформления (раздел 2 «Дизайн»). Без `alert/confirm` — только встроенные подтверждения.

## 4. Типы заданий и проверка

| type | Название | Ввод | Проверка |
| --- | --- | --- | --- |
| `choice` | Выбор ответа | тап по варианту | совпадение с `answers` |
| `fill` | Вставить слово | поле ввода; при нескольких пропусках — своё поле на каждый `___` прямо в тексте | список `answers`; при нескольких пропусках: все верны — 1, часть — 0,5, ни одного — 0, поля подсвечиваются по отдельности |
| `fix` | Исправить ошибку | исходное предложение в поле, правится целиком | список `answers` → иначе самооценка |
| `translate` | Перевод RU/UA → DE | поле ввода | список `answers` (1–5 вариантов) → иначе самооценка |
| `build` | Составить предложение | тап по словам (чипы из `text`, разделитель ` / `), тап по слову в строке убирает его, «Сбросить» | список `answers` |
| `combine` | Объединить / преобразовать | поле ввода, инструкция в `prompt` | список `answers` → иначе самооценка |
| `reflexive` | Местоимение и предлог | тап по варианту (как `choice`, варианты — готовые пары «mich auf») | совпадение с `answers` |

- `reflexive` сейчас только в блоке M: пара «возвратное местоимение + предлог» задаётся одним пропуском, `answers`/`options` — готовые двусловные фразы («mich auf», «sich für»); варианты различаются и местоимением (не тем лицом, что требует подлежащее), и предлогом. Рендерится и проверяется так же, как `choice` — отдельный `type` нужен только для того, чтобы в настройках пропорция между «только предлог» (`choice`) и «местоимение + предлог» (`reflexive`) была настраиваемым ползунком, как у остальных блоков.
- Сравнение: нижний регистр, без знаков препинания, схлопнутые пробелы. **Блок K** (`strict`) — регистр и запятые учитываются.
- Свободный ответ без точного совпадения → самооценка: свой ответ рядом с эталоном, кнопки «Верно / Почти / Неверно».

## 5. Формат данных

Источник правды — `data/blocks/<буква>.json`, один файл на блок (`A.json` … `M.json`), банк уровня A2–B2. Эта папка в `.gitignore` и не публикуется, как и `materials/`. `data/tasks.json` — собранный из блоков артефакт для приложения; он коммитится и публикуется (его грузит `index.html` на GitHub Pages), редактировать вручную не нужно. `scripts/build.py` добавляет в него (и в `data/tasks_a1a2.json`) поле верхнего уровня `"updated"` — дату сборки (`ДД.ММ.ГГГГ`); `index.html` показывает её на главной рядом с версией приложения и на экране «Как это работает» — это дата последнего обновления банка, отдельно от даты обновления текста самого экрана ⓘ.

Банк уровня A1–A2 устроен так же, но отдельно: `data/blocks_a1a2/<буква>.json` → собирается в `data/tasks_a1a2.json`. Это не подмножество основного банка, а свои, более простые задания — формат файлов одинаковый (см. ниже), только доступны 7 блоков (раздел 6).

`data/blocks/A.json`:

```json
{
  "name": {"ru": "Порядок слов, TeKaMoLo", "uk": "Порядок слів, TeKaMoLo"}, "level": "A2–B1",
  "rule": "краткое правило для подсказок и для ИИ (одноязычное, см. ниже)",
  "about": {"ru": "шпаргалка для попапа в квизе, строки через \n; строки, начинающиеся с |, — таблица", "uk": "..."},
  "example": "пример предложения для списка блоков",
  "types": {"build": 4, "fix": 2, "translate": 4, "combine": 0},
  "ex": "образцы заданий с курсов (необязательно, одноязычное)",
  "fixed": false, "strict": false,
  "tasks": [
    {"id": "A16", "block": "A", "type": "build",
     "prompt": {"ru": "Составьте предложение.", "uk": "Складіть речення."},
     "text": "am Montag / ich / habe / einen Brief / geschrieben",
     "answers": ["Am Montag habe ich einen Brief geschrieben."],
     "hint": {"ru": "1–2 предложения, почему так", "uk": "1–2 речення, чому так"},
     "options": ["только для choice, верный вариант внутри"],
     "note": {"ru": "необязательно: часть речи, напр. «предлог (например: mit, zu, von)»", "uk": "необов'язково: частина мови, напр. «прийменник (наприклад: mit, zu, von)»"},
     "tr": {"ru": "необязательно: перевод текста задания, показывается в объяснении после ответа", "uk": "необов'язково: переклад тексту завдання, показується в поясненні після відповіді"},
     "alt": {"ru": "необязательно: заметка про другие предлоги того же глагола (если есть)", "uk": "необов'язково: заувага про інші прийменники того самого дієслова (якщо є)"}}
  ]
}
```

Двуязычные поля (`{"ru": "...", "uk": "..."}`) — только там, где текст реально виден пользователю и зависит от языка интерфейса:
- на уровне блока: `about` всегда; `name` — немецкое название одной строкой, одинаковое на обоих языках (у блоков, которые ещё не переименованы, пока `{ru,uk}`); `example` — только если это не немецкий пример, а предложение на языке интерфейса (сейчас так только у блока L, «Смешанные переводы»);
- на уровне задания: `prompt`, `hint` всегда; `note`, `tr`, `alt` — если есть; `text` — только если он не чисто немецкий: у всех заданий типа `translate` и у части `choice`/`fill`, где в немецкий текст вшита подсказка-слово в скобках (например «(мой)»/«(мій)»).
Если значение поля одинаково на обоих языках (почти весь `text`/`example` — чистый немецкий) — оно остаётся простой строкой, оборачивать не нужно: `index.html` сам решает через `loc(v)` (строка — как есть, объект `{ru,uk}` — берёт нужный язык).
`rule` и `ex` — **не** двуязычные, остаются одной строкой (сейчас на украинском): не показываются пользователю, нужны только при написании новых заданий.

### Банк слов

Исходники — `data/words/<уровень>/<дата урока>.json` (`a2b2`, `a1a2`; в `.gitignore`, как и блоки), один файл на урок: `{"lesson": "2026-11-03", "title": "Lektion 1", "words": [...]}`. `scripts/build.py` собирает их в `data/words_<уровень>.json` (коммитится; каждому слову добавляется поле `lesson`) и проверяет `scripts/validate_words.py`.

Слово: `{"id": "W1", "de": "die Agentur", "pos": "noun", "ru": "агентство", "uk": "агентство", "pl": "-en"}`.
- `id` — `W` + номер, сквозной по всему банку уровня; никогда не меняется и не переиспользуется (на него ссылается прогресс).
- `pos` — `noun` / `verb` / `adj` / `other`. Существительное в `de` всегда с артиклем. У профессий/ролей — только мужская форма (`der Experte`), женскую (`die Expertin`) в банк не добавляем.
- `pl` (мн. число, как в учебнике) и `gov` (управление: `auf + A.`) — необязательны, показываются только после ответа.
- `ex` — обязательный пример: `{"de": "Ich bereite mich auf die Prüfung vor.", "ru": "...", "uk": "..."}` — короткое понятное предложение A2–B1 со словом в том значении, что в переводе, бытовая лексика; показывается после ответа под формой слова.
- `ru`/`uk` — перевод; значения через `,`, разные смыслы через `;`, уточнения в скобках. Два слова считаются «одинаковыми по смыслу», если совпала хоть одна часть перевода (без скобок), — такие не попадают в варианты одной карточки.

Правила данных (задания):
- `id` = буква блока + номер. **Никогда не менять и не переиспользовать id**: на них ссылается прогресс. Новые задания получают следующий свободный номер.
- `choice`, `fill` и `reflexive` — в `text` ровно один `___` (в `fill` допустимо `___ ___` для двух слов подряд). Исключение — `fill` с несколькими пропусками (окончания `Dies___ neu___ Auto`, `entweder … oder`): `___` на каждый пропуск, `answers[0]` — ответы по порядку через `, ` (`"es, e"`); в квизе каждый пропуск — своё поле в тексте. Если `text` двуязычный, у обоих языков `___` в том же месте немецкой части, отличается только вшитая подсказка в скобках.
- `build` — слова из `text` (без учёта регистра и знаков) совпадают со словами каждого ответа. `text` у `build` всегда одноязычный. Чипы — без знаков препинания (запятая в чипе подсказывает конструкцию и уводит к другому верному порядку). В `answers` — все естественные верные порядки, которые собираются из этих чипов (обстоятельство или подлежащее первым, придаточное до или после главного), иначе верный ответ уходит в самооценку.
- `fix` — `text` не совпадает ни с одним ответом. Всегда одноязычный.
- `types` блока — допустимые типы и стандартные пропорции; тип с 0 возможен, но по умолчанию не берётся.
- `tr` — необязательный перевод текста задания (готового предложения с верным ответом) на язык интерфейса, выводится в объяснении после ответа рядом с `hint`. Есть у всех заданий, кроме `translate` (там исходный текст и так на языке интерфейса), в обоих банках; у нового задания — обязателен. Для `fill`/`choice`/`reflexive` — перевод предложения с подставленным ответом, для `fix`/`build`/`combine` — перевод `answers[0]`.
- `about` (блок) — шпаргалка по грамматике блока для пользователя: строки «• правило + примеры» и, где нужно, таблицы (склонение, формы, пары союзов). Таблица — подряд идущие строки вида `| ячейка | ячейка |`, первая строка — заголовок (пустая ячейка допустима); `index.html` превращает их в `<table>`. Без без dessen/deren и прочего, чего нет в блоке; у A1–A2 — только урезанный охват темы. Обязателен (проверяет `validate.py`, как и `tr`). Не путать с `rule` — тот служебный, для составления заданий.
- `alt` — необязательная заметка о других предлогах того же глагола, когда они меняют смысл (например, у блока M: `sich freuen auf` — про будущее, `sich freuen über` — про случившееся). Выводится после `tr`, более тусклым цветом. Сейчас есть только у блока M, у ~20 глаголов блока с несколькими предлогами.
- Новое задание пишется сразу на обоих языках (`prompt`/`hint`/`note`/при необходимости `text` — как `{"ru":...,"uk":...}`); оставлять один язык пустым нельзя.
- После правок `data/blocks/*.json` и/или `data/blocks_a1a2/*.json` — собрать банки и прогнать проверку: `uv run scripts/build.py` (пересобирает оба банка — `data/tasks.json` и `data/tasks_a1a2.json` — и запускает `scripts/validate.py` для каждого: формат, дубли, `choice`/`build`/`fix`; проверки сами берут нужный язык через вспомогательную функцию `txt()`, которая понимает и простую строку, и `{ru,uk}`). Коммитить нужно только пересобранные `data/tasks.json`/`data/tasks_a1a2.json` — исходные `data/blocks*/*.json` не публикуются, живут только локально.

## 7. Как составлять задания

- Уровень A2–B2, бытовая лексика, без редких слов. Подсказки — 1–2 предложения, на обоих языках (раздел 5).
- Задания — **собственные примеры по правилу блока**. Тексты учебников не копировать; из материалов курсов берутся формат, сложность и темы.
- У каждого задания однозначный верный ответ. В `choice` дистракторы не должны быть тоже допустимыми (например, `helfen bei` — не давать `mit`; `schmecken nach` — не давать `wie`).
- `fix`: ровно одна ошибка — порядок слов, число или склонение (не опечатка). В K — заглавная буква, запятая, das/dass.
- `translate` и `combine`: перечислить 1–5 верных вариантов (порядок слов, синонимы, Perfekt/Präteritum).
- `note` — когда нужно вставить определённую часть речи: «предлог (например: mit, zu, von)», «возвратное местоимение (например: mich, uns, euch)», «относительное местоимение (например: der, den, dem)» — как и `prompt`/`hint`, двуязычно.
- Около 100 заданий на блок; у блока M ядро (глаголы с предлогами, `choice`) — фиксированный список из учебника, задания о возвратных глаголах (`choice`/`reflexive`) дописываются как обычно.

### Частые ошибки пользователя (учитывать при составлении)

- Порядок слов: подлежащее после союза (weil ich…); после je…desto — глагол сразу; weil и deshalb в одном предложении; Akk-местоимение перед Dat (ihn ihnen), два существительных — Dat перед Akk; nicht в конце.
- Времена: sein у глаголов смены состояния (aufstehen, bleiben, umziehen, fallen); fahren + прямое дополнение → haben; nachdem + Plusquamperfekt; als, а не wann; Plusquamperfekt только для более раннего действия; wird/werden по числу.
- Konjunktiv II: wäre без инфинитива, würde с инфинитивом; прошлое — hätte/wäre + Partizip II.
- Падежи: anrufen + Akk; Dativ при «кому», Dat. мн. ч. (mit den Kindern); sich Akk/Dat; предлог после глагола.
- zu-обороты: Lust haben + zu, zu у отделяемых приставок (zuzumachen), ohne/statt/um + zu.
- Перевод: внимательно читать исходный текст на языке интерфейса (из-за дождя / через дощ = wegen); орфография (Chef, schnell, solange).

## 8. Прогресс

- Хранится: по каждому блоку сумма баллов и число заданий за всю историю прохождений `{s, n}` (экран «Статистика» считает процент по ним); счётчик показов каждого задания; настройки; незаконченный тест; журнал последних 30 завершённых тестов (дата/время, блоки, сумма баллов и число заданий — для «Истории тестов» на главной). Всё это раздельно по уровню (A2–B2 / A1–A2) — свои ключи CloudStorage на каждый уровень.
- Слова: у каждого отвеченного слова `[верных подряд, в ошибках 0/1]`. Верно → счётчик +1, при 4 подряд слово уходит из «Ошибок»; ошибка → счётчик 0, слово в «Ошибках». «Новые» — слова из последнего пополнения банка: приложение помнит максимальный id банка и при его росте считает новыми id выше прежнего максимума (до следующего пополнения; при первом запуске новых нет — весь текущий банк считается уже загруженным). Колода незаконченного основного теста `{k: all, q: оставшиеся номера id, t, ok, bad, w: номера ошибок, mx}`; слова, добавленные в банк во время незаконченного теста, дописываются в конец колоды. Короткие тесты («Новые», «Ошибки») живут только в памяти до конца теста. Старый прогресс (ступени 0–5, ключи `dg_wp_*`) при переходе на эту логику не переносился.
- После завершённого теста: баллы и число заданий по затронутым блокам прибавляются к накопленным; в журнал истории добавляется запись теста, хранятся только последние 30 (запись ~100 символов, весь журнал укладывается в 4096 символов одного ключа).
- Выбор из банка: сначала задания, которые показывались реже всего, среди равных — случайно.

## 9. Telegram Mini App

- Статический сайт: `index.html` + `data/tasks.json` / `data/tasks_a1a2.json` (задания) и `data/words_<уровень>.json` (слова), хостинг GitHub Pages (HTTPS). Сервер не нужен. `index.html` грузит банк заданий уровня через `fetch` при старте, а банк слов — при первом входе в раздел «Слова» (нет файла — раздел сообщает, что слов для уровня пока нет).
- Без ИИ: только банк + самооценка.
- Хранение: `Telegram.WebApp.CloudStorage` (лимиты: 1024 ключа, значение до 4096 символов — прогресс и счётчики показов разбиты по ключам на блок: `dg_prog_<блок>`, `dg_seen_<блок>` для A2–B2 и `dg_prog_a1a2_<блок>`, `dg_seen_a1a2_<блок>` для A1–A2), запасной вариант вне Telegram — `localStorage`. Тема (`dg_theme`), язык интерфейса (`dg_lang`) и кнопки ä ö ü ß (`dg_uml`) общие для обоих уровней; уровень (`dg_level`), настройки теста (`dg_set`/`dg_set_a1a2`), незаконченный тест (`dg_run`/`dg_run_a1a2`; длинный — больше 4000 символов — делится на части `dg_run_0`, `dg_run_1`…, а в `dg_run` пишется `@<число частей>`) и журнал истории тестов (`dg_hist`/`dg_hist_a1a2`) — раздельные. Слова: прогресс разбит на ключи по 150 id — `dg_ws_<N>` / `dg_ws_a1a2_<N>` (N = номер id / 150), незаконченный тест — `dg_ws_run` / `dg_ws_a1a2_run`, граница «Новых» — `dg_ws_new` / `dg_ws_a1a2_new` (`начало,максимум`); скрытые слова — `dg_ws_hide` / `dg_ws_a1a2_hide` (номера id через запятую); направление (`dg_wdir`) и режим ответа (`dg_wmode`: `opt`/`type`) общие для уровней.
- Тёмный дизайн берёт из `themeParams` (с обновлением на `themeChanged`) только фон страницы и карточек (`bg_color`/`secondary_bg_color`) — акценты, текст и цвета верно/неверно остаются нашей палитрой, чтобы вид не зависел от случайной темы клиента Telegram у пользователя. Светлый и Glass themeParams не используют вовсе. Системная кнопка «Назад» (`BackButton`) дублирует внутреннюю навигацию, лёгкая вибрация (`HapticFeedback.impactOccurred('light')`) на ответах, `ready()` и `expand()` при старте.
- Бот через @BotFather; ссылка на Pages задаётся как Mini App / кнопка меню.

## 10. Порядок работы

- Каждое изменение логики или интерфейса → обновить экран ⓘ и этот файл.
- Перед каждым коммитом, меняющим `index.html`, — увеличить `APP_VERSION` в начале скрипта (`var APP_VERSION='v0.N'`, увеличивается число после точки). Он мелким шрифтом показывается внизу главного экрана — по нему пользователь видит, подтянулась ли свежая версия в Telegram (там агрессивный кэш WebView).
- Материалы курсов (страницы учебника) пользователь складывает в `materials/a2b2/` (для банка A2–B2) или `materials/a1a2/` (для банка A1–A2) — в `.gitignore`, не публикуется. Их разбор, распределение по блокам, дописывание заданий и пересборка банков — по скиллу `.claude/skills/fill-bank-from-materials`; если уровень материала не ясен, скилл сначала переспрашивает. Материалы, присланные прямо в чат (не через папку), скилл сам копирует в нужную `materials/<уровень>/` с датой в имени файла — исходники всегда архивируются хронологически в `processed/`, а не теряются во временной сессии. После обработки каждого материала скилл складывает исходники и журнал в папку дня — `materials/<уровень>/processed/ГГГГ-ММ-ДД/` (фото + `log.md`), несколько пополнений за день идут в ту же папку и тот же `log.md` (таблица-оглавление: дата, файлы, тема, блоки, диапазон id заданий; под ней по каждому материалу — исходные предложения, взятые в работу, по грамматическим блокам с id написанных по ним заданий, и что пропущено и почему) — чтобы можно было найти, из какого урока взялось задание, и при необходимости сгенерировать что-то кастомное на основе конкретного исходника.
- Слова для раздела «Слова» (страницы «Ihr Wortschatz» и т. п.) — по скиллу `.claude/skills/fill-words-from-materials`: он всегда уточняет уровень, архивирует фото в `materials/words/<уровень>/processed/ГГГГ-ММ-ДД/` с `log.md` дня, пишет слова в `data/words/<уровень>/<дата урока>.json` и пересобирает банк. Список «Скрытых» слов, присланный из приложения: плохой перевод/пример — исправить слово на месте (тот же id); слово не нужно — удалить из исходника (id не переиспользуется); затем пересобрать банк. Скрытие в приложении после этого остаётся — пользователь сам возвращает исправленные слова.
